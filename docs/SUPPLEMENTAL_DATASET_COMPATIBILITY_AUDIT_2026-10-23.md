# Supplemental dataset compatibility audit (2026-10-23)

This addendum covers sources missing from the main dataset ledger: all 30 named problems in the 2018 UEA multivariate time-series classification archive, the 2018 UCR univariate archive (128 constituent problems), ContentWise Impressions, SM-RS 2.0, additional CTR data, additional EEG/activity candidates, and ranking candidates Baidu-ULTR, T2Ranking, RCP-nDCG BRIGHT score fusion, and Tribler LTR. The final source sweep also checked WitFoo Precinct6 security events and ORBIT ClueWeb-Reco. It applies the same strict admission rule: task/labels, plain fixed-width MLP compatibility, anonymous no-gate download, reuse rights, whole-training-set single-batch feasibility, and an empirical non-saturation pilot must all pass. Missing evidence means cross out. The addendum does not claim a global census of the internet.

**Follow-up verification on 2026-10-24:** Tribler LTR's author-hosted split archive was fetched and parsed; it is crossed out under the full-batch `[512]*5` GPU resource requirement. Mendeley's Online Advertisement CSV was fetched without authentication and parsed; it is crossed out because the leakage-safe click target is over 98% positive in every chronological split, with only 84 negative rows overall, and the publisher says behavior is simulated. Per-candidate evidence and hashes are below.

## Repository architecture and task compatibility contract checked

Current source inspected: `src/simple_adp/models.py::TabularMLP`, `src/simple_adp/advanced_tasks.py`, `src/simple_adp/runner/datasets.py`, and `src/simple_adp/runner/sequence_datasets.py`.

- `TabularMLP` accepts a fixed-width dense numeric matrix and emits a fixed-width output vector. It has no sequence-aware recurrence, convolution, attention, or embedding lookup. Categorical IDs must be represented through the existing tabular preprocessing or deliberately excluded; integer ID magnitude is not a meaningful ordinal feature.
- `ForecastingTask` is fixed-horizon regression. A forecast example must be a causal fixed lookback and known covariates → fixed next-horizon target vector, with chronological target-position splits.
- `SequenceLabelingTask` emits a fixed number of per-step class logits from a flattened sequence window. Inputs and per-step targets must share a fixed window length; group split by source person/record/session before windowing.
- `EventDetectionTask` is supervised classification of event labels/windows and can compute event metrics when event IDs, source series IDs and window indices are carried in context. It does not transform an arbitrary anomaly score into ground truth.
- `GroupedRankingTask` scores candidate rows and requires `context['group_id']`; its pairwise loss uses relevance ≥ `relevant_threshold` as positive (default 4.0) and lower values as negatives. Binary click rows need threshold 1.0. It does not accept a listwise tensor as a substitute for grouped rows.
- Other datasets can use the generic regression/classification adapters when their labels are scalar/vector and split protocol is appropriate. A task adapter's availability is not itself proof of dataset compatibility or admission.

These constraints are applied below. Ranking candidates with text-only query/document content do not qualify merely because an MLP could technically be applied after introducing an unplanned language representation. “Compatible” means no architecture change and no unplanned representation family.

## UEA 2018: individual problem-by-problem ledger

The archive paper documents the count, dimensions, lengths, classes and train/test cases below. Its fixed-length multivariate sequences can be flattened into fixed-width MLP inputs. I independently probed the official per-problem ZIP endpoint for every row below; each returned HTTP 206 for a one-byte anonymous range request. The public Zenodo API metadata for all 30 exact UEA records also reports open access and CC BY 4.0; file names and sizes are recorded in [`UEA_2018_zenodo_rights_inventory.json`](data_audit_manifests/UEA_2018_zenodo_rights_inventory.json). Full exact payloads for 28 candidates have now been downloaded and parsed. Representative MLP pilots cover 27; StandWalkJump was crossed before training for 12-row support. FaceDetection and Cricket have separate source/task screens and were not fully downloaded because source access/rights already fail. The individual table below retains original metadata; new payload/header discrepancies and MLP results are detailed in the 2026-10-24 screen after this section. The table includes raw dense float32 training-input matrix estimates and first-layer weights+bias at width 512, not actual peak memory. Hidden activations, later layers, gradients, targets, optimizer state, and framework copies add substantially to observed peaks.

### EthanolConcentration: open source, parsed payload and low-skill pilot

The UEA page lists 261 train and 263 test examples, each with three 1,751-point spectra (5,253 flattened numeric inputs), four ethanol-concentration classes and 44 real whisky bottles. The exact UEA Zenodo record is [11206212](https://zenodo.org/records/11206212), open and CC BY 4.0. Both exact `.ts` files were anonymously downloaded and parsed; byte counts, hashes, class counts, and pilot details are in [`UEA_EthanolConcentration_pilot.json`](data_audit_manifests/UEA_EthanolConcentration_pilot.json). The UEA description says each instance contains repeat readings of the same bottle and batch, and the dataset comment describes predefined leave-one-bottle-out folds. However, the released train/test `.ts` rows have no bottle identity or fold assignment, so we cannot verify that the supplied official test split holds out bottles.

The full-batch GPU screen used a stratified utterance-row validation holdout (52 rows) from the 261-row train partition; statistics were fit only on the remaining 209 rows. With Adam 1e-3, cross-entropy, patience 20, and up to 100 epochs, `[128,128]` achieved .3194 test accuracy and `[512]*5` .3232, versus .25 chance. Both are far from saturation, but the MLPs show weak absolute skill, and the intended arbitrary-bottle generalization cannot be assessed on this split. **Cross out from the benchmark shortlist** for weak skill and unverified bottle-disjoint test construction, not for access or license. The similarly named UCR `EthanolLevel` Zenodo record is a separate artifact and was not used in this pilot. Sources: [UEA problem page](https://www.timeseriesclassification.com/description.php?Dataset=EthanolConcentration), [UEA Zenodo artifact](https://zenodo.org/records/11206212).

The real-data run peaked at 1,110 MiB, confirming comfortable fit. A class-stratified 20% validation holdout (500/class) left 20,000 training rows; mean/std were fitted only on those rows. Both repository `TabularMLP` pilots used 100 epochs, one full training batch per epoch, cross-entropy, Adam 0.001, seed 501, and selected checkpoints by validation accuracy. The official 25,000-row test split was untouched until checkpoint selection. Against 10% majority accuracy, `[128,128]` selected epoch 53 and scored 45.16% test accuracy/balanced accuracy, 44.85% macro-F1 and 2.706 cross-entropy. `[512]*5` selected epoch 93 and scored 50.07% accuracy/balanced accuracy, 49.84% macro-F1 and 4.404 cross-entropy. This is clearly non-saturated for both tested plain MLPs.

**Disposition: KEEP PROVISIONALLY** as a large, balanced, ten-class hard classification benchmark. It passes no-gate CC BY 4.0 access, fixed-width numeric MLP compatibility, full-batch GPU feasibility and empirical non-saturation. The source files carry no insect/specimen grouping IDs, so the official split's independence at specimen level is unverified; evidence is one seed and two architectures only. [Source paper](https://arxiv.org/abs/1403.2654).

### Handwriting: full payload and training-support rejection

The [UEA page](https://www.timeseriesclassification.com/description.php?Dataset=Handwriting) describes 26-letter classification from smartwatch motion and lists 150 training/850 test examples. The [Zenodo record](https://zenodo.org/records/11206227) is open/CC BY 4.0; both complete files were anonymously downloaded, parsed and hashed. The artifact header resolves the representation: three accelerometer channels ×152 points, 456 fixed numeric inputs, no missing values. It differs from an inconsistent UEA page paragraph that mentions six sensor dimensions. Train class support ranges from only 2 to 11 examples per class; test support ranges from 25 to 43. Exact class counts and SHA-256 values are in [`UEA_Handwriting_pilot.json`](data_audit_manifests/UEA_Handwriting_pilot.json).

I fitted per-feature mean/std on the 150 training rows and ran 100 fixed full-batch epochs with the repository `TabularMLP`, cross-entropy, Adam 0.001, seed 150 and RTX 3050 Laptop GPU. Test majority accuracy is 5.06%. `[128,128]` ended with train loss .00367 and test accuracy/balanced accuracy/macro-F1 26.24%/25.78%/24.26%; `[512]*5` drove training loss to .00000435 while scoring 20.94%/20.73%/19.16%. No validation set or test-based checkpoint selection was used. The UEA record does not retain person IDs, so subject independence cannot be checked.

**Disposition: CROSS OUT for reliable architecture comparison.** The task is MLP-compatible, openly downloadable and far from saturation, but only 150 train examples for 26 classes lead to near-total training fit and weak held-out performance; the larger model performs worse, and person-level split status is unknown. This is too little evidence for a stable comparison among the planned architecture-search methods.

### Epilepsy: complete individual payload and task-validity screen

The public [Zenodo record](https://zenodo.org/records/11206204) gives open access and CC BY 4.0. ### BasicMotions: complete individual payload and sample/split rejection

The [Zenodo record](https://zenodo.org/records/11206179) reports open access and CC BY 4.0. ### FaceDetection: candidate-source and access/rights rejection

The [UEA per-dataset page](https://www.timeseriesclassification.com/description.php?Dataset=FaceDetection) describes 5,890 training and 3,524 test MEG trials, with face versus scrambled-image labels and a subject-disjoint split (10 train subjects, 6 test subjects). ## ContentWise Impressions

- **Task fit:** supervised recommendation/click response is supported by impression rows; preserve slate membership and evaluate groupwise ranking or pointwise response as appropriate. The paper distinguishes impressions with direct interaction links from impressions with none, so target construction must preserve this distinction and must not naively label all unlinked recommendations as explicit negatives without reviewing the authors’ semantics.
- **Scale:** paper counts 10,457,810 interactions, 307,453 directly linked impressions, and 23,342,617 impressions without a direct link; 42,153 users and 145,074 items. Under this repo’s all-training-rows-at-once and dense one-hot policy, this is incompatible with the full-batch profile. IDs would create very wide inputs; using embeddings/sampling would change the required model/training profile.
- **Access/rights:** the GitHub instructions say the form to obtain the link is optional and will not block access; the exact archive link and archive README were not retrieved during this audit. The dataset paper explicitly gives CC BY-NC-SA 4.0. That noncommercial/share-alike license fails the suite’s unrestricted reuse gate. The code repository is AGPL-3.0; that is not the data license.
- **Difficulty:** no MLP training pilot or non-saturation result was obtained. It cannot be labeled hard or admitted based on row count alone.
- **Decision:** cross out because of license incompatibility and full-batch scale, with acquisition and empirical gates also unverified.

The nominal feature shape (11 numeric-coded attributes after the binary click target) is an excellent mathematical fit to a dense MLP; OpenML metadata describes impressions, URL/ad/advertiser IDs, depth, position, query, keyword, title, description, and user IDs. No complete payload, hash, parser, split protocol, or vanilla MLP pilot was verified. **Cross out pending authoritative rights/access clarification and non-saturation testing.** Do not treat the 1% sample as proof the full source is licensed for unrestricted use. [OpenML API metadata](https://www.openml.org/api/v1/json/data/1219); [original KDD Cup description](https://www.kdd.org/kdd2012/kddcup.shtml.html); [Kaggle competition data page](https://www.kaggle.com/c/kddcup2012-track2/data).

## SM-RS 2.0 (recommendation interaction, propensity, and perception benchmark)

- **Task fit against this repository:** the repo's regression adapter can represent fixed tabular features to a scalar or four-value target, so user propensity, perceived quality, or satisfaction regression are plausible MLP tasks. Flattened exposed-candidate rows could support click classification, and `GroupedRankingTask` could score candidates while retaining impression IDs as group context. However, the benchmark has six distinct tasks and some require recomputing item-item relevance, diversity, or popularity matrices from separate MovieLens/goodbooks source data. Those are not equivalent to a single generic accuracy target. Each must be separately specified; task 2's list-level proportionality and task 4's diversity-metric definition are not automatically supervised row-classification tasks.
- **Public access and rights:** the Hugging Face dataset card identifies CC BY 4.0 for the collected study data, says the item tables reference MovieLens/goodbooks IDs without redistributing those catalogs, and documents anonymous load instructions. In this turn all eight exact Parquet files were fully fetched anonymously, read with pandas/pyarrow, and schema-checked. This establishes a complete no-login download and parse for the pinned current files, not a hash-pinned hosted revision.
- **Parsed payloads:** `behaviors.parquet` 9,806 × 7; `books.parquet` 6,548 × 3; `comparative_diversity.parquet` 432 × 5; `criteria_values.parquet` 9,806 × 5; `movies.parquet` 15,876 × 2; `objective_perceptions.parquet` 848 × 9; `propensities.parquet` 3,529 × 6; `users.parquet` 435 × 12. The behavior rows contain nested exposed-item lists, not a flat candidate table. Expanding all nested lists yields 397,761 candidate rows and 26,654 selected items in the acquired payload. Combined one-hot user/item IDs produce width 16,251 and a raw full matrix of 24,658.3 MiB float32, before any network/optimizer memory.
- **Task-by-task compatibility and disposition:**
  - **Task 1 propensity estimation:** 3,529 four-target records across 435 users. The tested fixed input was clicked-item plus exposed-item multi-hot vectors (44,848 columns), a bag-of-items summary of the benchmark's variable histories/impressions; it omitted the user-ID and timestamp fields. A five-fold user-held-out pilot with masked MSE, full-batch Adam (1e-3), and 30 epochs gave constant-baseline MAE/MSE `0.1114/0.0221`, `[128,128]` MLP `0.1075/0.0208`, and `[512]*5` MLP `0.1100/0.0218` on observed target cells. **Cross out this tested encoding:** the MLPs scarcely improve on the constant baseline. This does not rule out every possible Task-1 feature design.
  - **Task 2 proportional recommendations:** the output is a top-k list optimized against target objective proportions. Scoring requires relevance, diversity, novelty and exploration matrices, which are not part of the CC-BY study tables and must be recomputed from separately licensed MovieLens/goodbooks sources. **Cross out for this repository's self-contained benchmark:** missing required matrices/source licenses and this is list construction rather than a direct fixed-row supervised target.
  - **Task 3 selections-aware reranking / click prediction:** each exposed item has a `selected` label, so an MLP scorer is structurally compatible with `GroupedRankingTask`. The full payload contains 397,761 candidate rows, 15,816 item IDs and 435 user IDs; one-hot user+item features alone require 24,658.3 MiB for the float32 input matrix. **Cross out under the current all-training-rows-in-one-batch profile** before model activations or optimizer state.
  - **Task 4 comparative list-diversity prediction:** 432 examples each contain three fixed lists of eight items and three perceived-diversity labels; these can be encoded as three-slot multi-hot input and a three-value MLP output. But the released table has no participant ID, while the paper says the 432 judgments came from Studies C/D with 107 and 101 valid participants. A participant-disjoint split cannot be constructed or checked. **Cross out:** 432 rows, unknown respondent overlap, and no defensible held-out-person difficulty result.
  - **Task 5.1 perceived relevance:** use the benchmark's multi-hot set of items shown in the impressions linked by each questionnaire response; 848 rows, 434 users. Five-fold user-disjoint CV, seed 2024; each fold trained for 30 full-batch epochs using Adam (1e-3), MSE, sigmoid output, and this repo's `TabularMLP` at `[128,128]` and `[512]*5`. Out-of-fold MAE/MSE/Kendall tau-b: constant `0.1901/0.0611/-0.0376`; `[128,128]` `0.1823/0.0582/0.2167`; `[512]*5` `0.1965/0.0664/0.1748`. **Keep provisionally:** scores are far from saturation and width changes generalization, although the cohort is small and the wide model is worse.
  - **Task 5.2 perceived diversity:** same input and split. Constant `0.2168/0.0654/-0.0305`; `[128,128]` `0.2048/0.0652/0.2080`; `[512]*5` `0.2243/0.0767/0.1803`. **Keep provisionally** with the same small-cohort/wide-model caveat.
  - **Task 5.3 perceived novelty:** 835 responses / 430 users. Constant `0.2550/0.0817/-0.0540`; `[128,128]` `0.2583/0.0981/0.1100`; `[512]*5` `0.2545/0.0950/0.1179`. **Cross out for weak held-out-user signal:** neither MLP improves MAE/MSE over the constant baseline.
  - **Task 5.4 perceived serendipity:** only 620 responses / 208 users. Constant `0.2455/0.0724/-0.0595`; `[128,128]` `0.2549/0.0926/0.0195`; `[512]*5` `0.2574/0.0939/-0.0114`. **Cross out:** small effective sample and no skill over the mean baseline.
  - **Task 6.1 satisfaction from shown-item histories:** same item multi-hot input, 848 rows / 434 users. Constant `0.2113/0.0708/-0.0388`; `[128,128]` `0.2114/0.0739/0.1252`; `[512]*5` `0.2289/0.0857/0.0955`. **Cross out for weak held-out-user signal:** neither MLP improves MAE/MSE over the constant baseline.
  - **Task 6.2 satisfaction from perceived-quality attributes:** five perception values plus five train-fold-fitted missingness indicators/median imputations; same user-disjoint split. Constant `0.2113/0.0708/-0.0388`; `[128,128]` `0.1864/0.0527/0.5035`; `[512]*5` `0.1322/0.0329/0.5273`. **Keep provisionally:** both MLPs improve substantially over the constant baseline without saturating, but this task uses contemporaneous perception answers as predictors by design and needs broader replication before a general recommendation claim.
- **Pilot protocol and limits:** the grouped folds were formed by shuffling 434 user IDs with NumPy seed 2024 and splitting them into five folds. Each fold's entire training partition was one batch. The pilot ran on an NVIDIA GeForce RTX 3050 Laptop GPU (6 GB). Tasks 5/6 used fixed 22,424-column multi-hot item vectors (movie and book IDs kept disjoint); no user IDs or target-derived values were input in Tasks 5.1–6.1. Task 6.2 used the five perception columns, with medians fit on each training fold and missingness indicators. Kendall values above are tau-b from the pilot, not the benchmark's tau-c; MAE/MSE use the same definitions. This screened Vanilla MLP behavior only; ADP variants and the central runner were not exercised on these routes.
- **Overall disposition:** SM-RS is verified as anonymous, downloadable and CC BY 4.0 under its card, and fully parsed. Keep **Tasks 5.1, 5.2 and 6.2** as provisional small-cohort perception/satisfaction regression routes. Cross out the other individual task routes for the stated reasons. This is not ADP-wide validation.

## Event-detection source and full-payload screen: University of Padua alarm logs

The [official University of Padua record](https://researchdata.cab.unipd.it/1031/) lists the archive, code, and README as visible to anyone under CC BY 4.0. The 8,517,314-byte ZIP was downloaded without login and passed ZIP integrity validation. It contains raw `alarms.csv` (444,834 rows; 20 machine serials; 154 alarm codes), plus processed sequence files. The downloaded processed NPZ contradicts the README on output sequence width: `x_train=(41045,109)` and `y_train=(41045,556)` rather than both widths being 109. This route uses raw data and keeps that discrepancy visible.

A fixed-width, supervised event-occurrence task was tested: six prior hours of alarm-code counts (154 numeric inputs) predict whether any alarm occurs during the next hour. Examples are hourly and never cross machine boundaries; 12 machines train, four validate, and four test using seed 20261023. The one-batch partitions contain 119,484/25,761/31,271 examples. Train-only standardization was applied. Three repo `TabularMLP` architectures ran 30 CUDA epochs with full-batch Adam and cross-entropy. Test accuracy / balanced accuracy / macro-F1 / positive-event F1 are `[16,16]` .6801/.5818/.5610/.3324, `[128,128]` .7651/.7263/.7344/.6442, and `[512]*5` .7703/.7403/.7457/.6666. Peak CUDA memory was 1.737 GiB for the largest model. The model scores are unsaturated and widen with architecture, but a prior-hour alarm persistence rule scores .8491 accuracy/.8372 balanced accuracy/.7932 event F1, outperforming each MLP. **Keep only provisionally as a hard event-detection stress route, with persistence required as a baseline.** The test event rate is 36.47% while validation is 16.69%, showing group shift. Only one group split/seed and three vanilla architectures were tried; no ADP variants or runner provider was evaluated. Full protocol and hashes: [`UNIPD_PACKAGING_ALARMS_SCREEN.md`](data_audit_manifests/UNIPD_PACKAGING_ALARMS_SCREEN.md) and [JSON manifest](data_audit_manifests/UNIPD_PACKAGING_ALARMS_SCREEN.json).

The dataset's other described tasks were checked separately at the representation level. Next-alarm-type classification is potentially a standard multi-class MLP task, but this group split has alarm classes in held-out machines absent from training, so a general 154-class score would be invalid without a new justified split/task definition. Future-window alarm prediction is multi-label; the current event adapter is single-label and does not implement that output/loss. Future alarm-sequence prediction needs 556 output positions by up to 154 alarm classes (85,624 logits/example) and the provided NPZ/README length mismatch must be resolved; this dense output is not currently a supported/feasible runner route. ## MetroPT-3: full payload, supervised event support, and one-hour sensor forecast

The official [UCI record](https://archive.ics.uci.edu/dataset/791/metropt%2B3%2B) is public, declares CC BY 4.0, provides a direct ZIP, and states the first month may be used for training with the remainder for testing. The complete 218,381,995-byte ZIP downloaded anonymously; ZIP CRC validation passed. It contains `MetroPT3(AirCompressor).csv` (218,300,507 bytes, SHA-256 in the manifest), which parses to 1,516,948 rows, timestamp plus 15 sensor signals and an index column, with no missing cells. Although the UCI page has inconsistent cadence descriptions (1 Hz in one section and 0.1 Hz in another), observed timestamps are mostly 10 seconds apart (with 9-, 11-, 12-, and 13-second intervals), spanning February 1 to September 1, 2020.

### Supervised failure/event task: crossed out

UCI explicitly calls the sensor series **unlabeled** and provides four company-reported air-leak failure periods: April 18, May 29–30, June 5–7, and July 15, 2020. All occur after the recommended February training month, so that training split has zero positive event examples. There is one compressor, not independent train/test assets. A supervised event classifier cannot be trained and tested credibly from four episodes under the source's chronology. **CROSS OUT for supervised failure or event detection.** This is not a negative finding about MLP architecture; the required supervised labels and positive training support are absent.

### Numeric sensor forecasting task: crossed out after a full-batch pilot

To test the separate forecasting use case without carrying 1.5m raw rows into each dense batch, I formed fixed ten-minute means over the source's continuous telemetry. A bin was retained only when at least 45 raw readings were present. The MLP sees six prior ten-minute bins (90 values across all 15 sensors) and forecasts the next hour's mean for seven analog channels: TP2, TP3, H1, DV_pressure, Reservoirs, Oil_temperature and Motor_current. Each of the six input and six target bins must pass the same record-count gate.

The split is chronological and respects the UCI suggestion: training covers 80% of February, validation the remainder of February, and test starts March 1 and runs to August 31. Train/validation/test sizes are 2,670/608/19,509. Input and target standardization used training data only; full-batch Adam at 0.001, MSE, 30 epochs, and validation-MSE checkpoint selection were used on CUDA. This transformed task used one full training partition per epoch.

## PIADE: one-hour packaging-machine alarm-count forecasting screen

The University of Padua [Research Data record](https://researchdata.cab.unipd.it/1459/) identifies the PIADE files as visible to anyone and licensed CC BY 4.0. The matching [Zenodo record](https://zenodo.org/records/7071747) offers separate raw and one-hour sequence CSVs; its page does not populate the license field, so the rights conclusion comes from the official University record. I anonymously downloaded the sequence artifact in full (11,663,660 bytes); its computed MD5 matches Zenodo's published `5edf8a6806f272228d522c76825d955c`, and SHA-256 is recorded in the manifest. The sequence artifact parses as 23,376 rows × 164 columns across five packaging machines. ## Scope and evidence boundary

This is an exhaustive itemization of the 30 UEA records and 128 UCR names, with anonymous range probes for all 30 UEA ZIP endpoints, full anonymous downloads and parses of 28 UEA archives, bounded MLP pilots on 27, and a complete official UCR metadata spreadsheet download and row-by-row screen; it is not an exhaustive search of all datasets worldwide. The provisional UEA set is Epilepsy (controlled activity classification), LSST (hard imbalanced classification), RacketSports (small non-saturated wearable activity), HandMovementDirection (difficult MEG classification), InsectWingbeat (non-saturated insect classification), PhonemeSpectra (hard 39-class task), NATOPS (non-saturated balanced gesture classification) and PEMS-SF (non-saturated weekday classification with calendar-correlation caveats). The remaining 22 UEA candidates are crossed for near-ceiling MLP skill, weak/no generalization, insufficient samples/groups, data provenance/split inconsistencies, or rights/access limits, with exact reasons and observed pilot results in the problem-by-problem table. All 128 named UCR candidates have row-level task/shape/standard-baseline screens and are crossed for the UCR bundle route because the archive requires a published password and provides no explicit blanket or per-constituent reuse license. This is not an audit of separate upstream artifacts/licenses or MLP saturation for those 128. Other supplemental candidates remain crossed where a hard gate fails or key evidence is missing. Promotion requires the exact artifact/license, parsed task and split, full-batch resource check, and empirical MLP pilot.

## OD-TINA: industrial event labels and pointwise batch feasibility

The official [OD-TINA repository](https://github.com/ari-dasci/OD-TINA) is public, declares CC BY-SA 4.0, and exposes 468 dated Parquet partitions (about 1.345 GB in the recursive GitHub tree); a representative Parquet partition was previously fetched without authentication and parsed as 74,026 × 108 with no missing cells. The README describes 38+ million observations, 108 columns, 2-second nominal cadence, 103 numeric feature columns, two additional categorical feature columns, and categorical `m_id`, `m_subid`, and `alarms` labels. It reports 191,241 maintenance events and 587,398 alarms. Source metadata and the one-file probe establish public access and fixed-width numeric MLP compatibility for a rowwise supervised classifier.

This does not qualify as a viable full-batch benchmark route. Training on all 38 million rows at once violates the suite's whole-training-partition single-batch rule and is far beyond the RTX 3050's memory budget. A stride sample (for example, retaining every 120th observation) would change event support and can miss short-duration labels; it is not accepted as a faithful event benchmark absent label-duration/aggregation rules and a pilot. A full anonymous fetch and parser pass over all 468 partitions was attempted for that screen but could not complete from this machine because outbound GitHub TLS connections remained in SYN-SENT; no full-payload hashes or split-specific label counts were obtained. Thus public listing, open license, and one-partition download are verified, but exhaustive all-partition downloadability and empirical non-saturation are not. **Cross out OD-TINA for this suite under the current full-batch protocol**; reconsider only if the benchmark rules explicitly permit a documented temporal aggregation/window task that preserves event labels and can be evaluated as its own task. This is not a claim that the dataset is intrinsically unsuitable for anomaly detection. Detailed evidence and boundaries are in [`OD_TINA_SCREEN.json`](data_audit_manifests/OD_TINA_SCREEN.json).


## PhysioNet MIT-BIH Atrial Fibrillation Database (AFDB): full payload and record-held-out MLP screen

The official AFDB v1.0.0 page marks the database Open Access under the Open Data Commons Attribution License v1.0 and documents both an anonymous `wget` URL and `aws s3 sync --no-sign-request` from `physionet-open/afdb/1.0.0`. I fetched the public S3 listing (156 objects; 635,350,603 bytes) and all listed objects. The release's `SHA256SUMS.txt` covers 155 objects; every such file matched its published digest and listed byte count. The manifest itself was fetched from the same public prefix and hashed locally. S3 ETags for multipart files were not treated as content hashes.

The official record describes 25 long-term recordings. Twenty-three have two 250 Hz ECG channels; 00735 and 03665 have annotation files but no signals. The current `.atr` files contain manually prepared AFIB, AFL, J and N rhythm markers; N denotes all other rhythms. I parsed all 23 signal records, their headers, and their `.atr` annotations. Records 04043, 08405 and 08434 include 10.24-second zero-filled sections for unreadable tape blocks; all-zero windows were removed. Published literature also excludes records 04936 and 05091 because their rhythm labels have been reported incorrect, so they are omitted from this task. The complete per-record counts and 156-file inventory are in the manifest.

The route is mechanically compatible with the current fixed-width MLP: non-overlapping 10-second windows are flattened from two leads to 5,000 numeric features; only fully annotated windows contained in a single rhythm interval remain; AFIB is positive and AFL/J/N are grouped as other. The split is by record, with no overlap: 15 train records, 3 validation records and 3 test records. The three split lists are frozen in the manifest. This is a rhythm-window task within a cohort where all patients had at least one AF episode, not general-population screening.

Using the repository's `TabularMLP`, I ran 30 epochs with the entire training partition as one batch per step, Adam at 0.001, inverse-frequency weighted cross-entropy, training-only per-lead standardization and best-validation-AP checkpoint selection. The train/validation/test sizes were 54,510/10,987/10,972. The three representative vanilla architectures `[16,16]`, `[128,128]` and `[512,512,512,512,512]` used 1.46, 1.55 and 2.21 GiB peak allocated GPU memory on an RTX 3050 6 GiB. Their test AP values were .341/.340/.370 against test AF prevalence .372; test ROC-AUC .415/.353/.519; validation-F1-selected threshold balanced accuracy .500/.430/.506. Validation AP was much higher (.836/.784/.818), which did not hold on the test records.

**Disposition: CROSS OUT from the shortlist.** The exact record-disjoint test does not show useful generalization or headroom: test AP is at or below prevalence, and ROC-AUC and thresholded balanced accuracy are near chance. This rejects this split/window/optimization route for the requested benchmark suite; it does not prove that every AFDB protocol or representation fails. Only three vanilla architectures, one split and one seed were piloted. The full result and provenance are in [`PHYSIONET_AFDB_SCREEN.json`](data_audit_manifests/PHYSIONET_AFDB_SCREEN.json).


## PhysioNet EEG Motor Movement/Imagery (eegmmidb): complete selected-run payload and subject-held-out pilot

The official v1.0.0 page identifies the release as Open Access under ODC Attribution 1.0 and provides anonymous `wget` and no-sign-request S3 download routes. I listed the public S3 prefix for every subject S001–S109 and fetched only runs 04, 08 and 12, the three repetitions of the imagined left-versus-right fist task. The exact selected payload contains 327 EDF files (833,940,288 bytes). All files passed listed-size and single-part 32-hex S3 ETag/MD5 verification; individual SHA-256 values are recorded in the manifest.

I parsed all 327 EDFs with 64 EEG channels and the embedded task annotations. The official archive identifies T0 as rest, and T1/T2 as left/right fist actions for runs 3, 4, 7, 8, 11 and 12. For each T1/T2 event lasting at least four seconds, the task row uses the first four seconds from that event onset; T0 is excluded. Source rates vary: 318 files are 160 Hz and nine are 128 Hz. The 160 Hz windows were anti-aliased polyphase-resampled by 4/5 to a common 128 Hz; all windows then have 64 ×512 samples, flattened to 32,768 numeric features. This remains a plain feedforward MLP input, without a learned signal encoder. Per-channel mean and standard deviation were fitted only to training-subject windows.

The deterministic subject-disjoint split used NumPy `default_rng(20261023)`: 76 train subjects, 16 validation subjects and 17 test subjects. It yielded 3,435/717/765 windows; class counts were 1,736/1,699, 357/360 and 386/379 for left/right fist respectively. Training used the repository's `TabularMLP`, 30 full-batch epochs, Adam at 0.001, cross-entropy and best-validation-macro-F1 checkpoint selection on the RTX 3050 6 GiB GPU. `[16,16]`, `[128,128]` and `[512]*5` achieved held-out test accuracy and macro-F1 of .800/.800, .805/.805 and .814/.814, against .50 chance; peak allocated GPU memory was 642/712/972 MiB. None saturated, and each shows useful subject-held-out signal in this screen.

**Disposition: KEEP PROVISIONALLY as one motor-imagery classification/temporal-window route.** The result is a bounded screen: one split and seed, three representative vanilla architectures, and no central runner or ADP-variant integration. Do not generalize this score to other EEG tasks or all subjects/splits. Exact source inventory, hashes, parsed run metadata, split, and results are in [`PHYSIONET_EEGMMIDB_SCREEN.json`](data_audit_manifests/PHYSIONET_EEGMMIDB_SCREEN.json).

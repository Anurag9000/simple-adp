## Decision and evidence rules

“No-gate” here means that an ordinary researcher can reach the dataset payload from an authoritative repository/official mirror without account creation, application, institutional affiliation, credentialing, or acceptance of a dataset-specific click-through agreement. A public page alone is insufficient. A source may be download-open yet still carry a noncommercial, attribution, redistribution, or original-source license condition; those conditions are stated separately. Some hosts block automated clients, so the direct-download check distinguishes a successful HTTP probe from an endpoint that was advertised by its primary source but not independently confirmed by this environment.

Every eligible record below has a public authoritative source and a technically plausible path to a fixed-width MLP input/target pair. “Compatible” means compatible after ordinary tabularization, not that a flattened MLP is the best model or that sequence semantics can be ignored. No benchmark result or model accuracy is implied.

The A–E tables are candidate discovery inventories; phrases such as “eligible with terms” describe only a potentially public source route, not acceptance into this benchmark suite. The final decision is in K1/K2. A fully admitted benchmark must pass task/label compatibility, the permitted MLP representation, a no-gate payload route, reuse-rights review, the whole-training-partition batch/resource constraint, and an empirical non-saturation screen. A candidate with successful checks but a missing integration or task-specific check may be retained as **provisional**; it must not be described as fully admitted. A candidate failing or lacking a core access, rights, resource, or empirical gate is crossed out. An unresolved check is not evidence of a dataset defect; it is insufficient evidence for full admission.

The source-route catalog uses four evidence labels:

- **Eligible:** no-account public artifact and a reasonably clear reuse license or public benchmark terms.
- **Eligible with terms:** direct public artifact, but noncommercial/research-only, attribution, or source-specific rights need to be followed.
- **Conditional:** a discovery-table status only; it is not admitted. License/provenance, artifact, or split evidence remains unresolved and the candidate is crossed out in the final suite ledger.
- **Exclude (gated):** account, application, or dataset-specific agreement is required.

For the current pressure-aware comparison profile, “whole batch” means every training example is in the same batch for each epoch, as requested for this suite. Dense one-hot ID features and all activations are included when judging scale. Embedding tables, negative sampling, candidate sampling, streaming, or smaller batches would define a different input/training profile and do not rescue a candidate in this ledger.

The compatibility target is the repo's `TabularMLP` in `src/simple_adp/models.py` (fixed-width dense inputs and hidden layers), coordinated through `src/simple_adp/runner/datasets.py` providers and task adapters in `src/simple_adp/advanced_tasks.py`: `ForecastingTask`, `SequenceLabelingTask`, `EventDetectionTask`, `GroupedRankingTask`, and the supervised preference/anomaly adapters. This audit allows only flattened fixed-window or structured numeric/categorical rows; it does not assume convolution, recurrence, attention, learned embeddings, or text encoders. A task adapter being present establishes an interface path, not dataset admission.

## Plain MLP conversion contract

- **Forecasting:** for each series, form rolling-origin examples `(lookback values + known covariates) -> next H values`; flatten the fixed lookback and covariates into one vector and predict H outputs. Split by time, never randomly across windows. Fit imputation/scaling on each training fold only. Keep each series' frequency, seasonal period, horizon and original train/test boundary in metadata. Do not train on future parts of a series or on test targets.
- **Sequence prediction/labeling:** make fixed-width windows of `lookback × channels`; predict either the central/next timestep label (sequence-to-one) or the labels for all positions in the window (sequence-to-sequence). The latter is an MLP with a fixed number of output slots, not a recurrent model. Split by subject/session/recording first, then window, to avoid near-duplicate leakage. Never let overlapping windows cross split boundaries.
- **Event detection:** use the same windowing with a precisely defined target: event-in-window, event-at-center, event type, or the vector of per-timestep labels. Define event tolerance and metrics before comparing models; reporting one row per point as accuracy can hide severe imbalance. Streaming benchmarks need causal windows and must not expose post-event context.
- **Ranking:** a row is a query-document (or query-item) candidate and the tabular features are its inputs. Retain query/group IDs outside model features; score items independently with the MLP and compute ranking metrics grouped by query. A pointwise MLP is directly compatible. Pairwise/listwise objectives can be custom task adapters but require group-aware batches; treating query IDs as ordinary numeric features is invalid.
- **Recommendation:** a row is a user-item interaction or exposed candidate. Numeric/categorical IDs can be one-hot/tabularized for a plain MLP, with severe scale/cardinality implications. Preserve timestamps, exposure/impression status, and user/item groups. Use chronological or official split protocols. Randomly splitting interactions may leak a user's future history. Unobserved implicit-feedback pairs are not automatically negatives.

**“Tabular” boundary:** these are time-indexed rows or event/interaction tables, or raw series that can be represented by fixed windows. The catalog excludes image/text payloads as model inputs. A dataset containing free text is suitable only when the benchmark provides structured features/IDs and the text is omitted; no language encoder is assumed.

## H. Final admission shortlist

Twenty dataset families, covering 86 time-series task routes/horizons, remain on the provisional admission shortlist after bounded vanilla MLP screens. This count includes the previously documented PIADE forecast and University of Padua alarm-count stress route, plus the newly screened MIT-BIH SVDB and EEGMMIDB tasks; it excludes every crossed-out candidate:

1. **Forecasting:** Monash Australian Electricity Demand, horizons 1, 7, and 28. Public CC BY 4.0 artifact and full provider parse verified. All three were trained through 30 full-batch epochs at widths 16 and 128; validation R² remained below -1.9. This proves no saturation at these settings, while also exposing weak absolute performance in the current target-scaling/training setup.
2. **Forecasting candidate:** UCI Appliances Energy Prediction, one-hour-ahead six-step forecast. The official UCI API CSV downloaded anonymously as 4,489,645 bytes, parsed as 19,735 × 29 with no missing cells (SHA-256 recorded in K4a). The tested causal input has 384 features: twelve historical ten-minute rows of 26 observed variables plus cyclical time fields and known future calendar fields; random `rv1/rv2` columns were excluded. Chronological 70/10/20 target-position split produced 13,797/1,969/3,942 train/validation/test examples. A standalone `TabularMLP` pilot used full-batch Adam (1e-3), train-only feature/target scaling, MSE, and 30 epochs. Validation R² was 0.253/0.261 and test R² 0.215/0.218 for `[128,128]` / `[512]*5`; persistence test R² was -0.068. This shows useful forecasting signal without saturation at the tested sizes, but the route has not been implemented in the runner or tested with ADP variants.
3. **Forecasting candidate:** UCI Beijing PM2.5, six-hour-ahead from a 24-hour lookback. The official 2,012,559-byte API artifact was downloaded anonymously and parsed; UCI labels it CC BY 4.0. A chronological split, train-only imputation/scaling, and 30-epoch full-batch `[128,128]` / `[512]*5` GPU pilot were used. Test RMSE was 50.79 / 45.58 versus 46.31 persistence; test MAE was 34.18 / 29.97 versus 26.84 persistence. It is unsaturated and width-sensitive but only the wide MLP modestly beats persistence on RMSE; not runner-integrated or ADP-tested.
4. **Forecasting:** UCI Metro Interstate Traffic Volume, with a six-hour horizon from contiguous hourly traffic/weather windows. The official archive was anonymously downloaded and parsed; duplicate timestamp target values agree, and windows skip timestamp gaps. Full-batch `[128,128]` / `[512]*5` 30-epoch pilots achieved test RMSE 815 / 720 and R² .828 / .866, versus persistence RMSE 2,107. The task is unsaturated and width-sensitive; standalone, not runner/ADP tested.

Do not choose a dataset solely because it is large or difficult. Freeze source version, archive hash, license text, split generation, preprocessing, label definition, and metric in a manifest. First validate leakage, label semantics and class imbalance on the raw data. MLP parameter count scales with flattened window width, so record actual transformed feature dimension and reject runs that exceed explicit resource limits.

## J. Limits of this review

This is an extensive catalog over the named primary benchmark repositories and verified candidate families, not a global census of all online data. Some sources have been verified at landing-page and endpoint level but not downloaded, checksum-validated, parsed, or audited row-by-row. License conclusions are scoped to the cited version and available metadata; record the exact license file at acquisition. A “download open” finding does not grant rights to redistribute the downloaded payload. For any candidate reconsidered later, the next step is a bounded acquisition audit: resolve its exact archive URL, download to a temporary/cache location, verify a published checksum where available, parse labels and partition files, inspect license and schema, and recalculate full-batch memory for the largest registered model. Only then run the exact difficulty pilot and consider adding it to the runner catalog. Four source families have passed the runner-path acquisition/parser/split/pilot stages; Apnea-ECG still needs a built-in provider. UCI Appliances has a standalone pilot but no provider/runner verification.

### K2b. OpenSTEF Liander 2024: all 55 load targets individually screened

The public [OpenSTEF Liander 2024 benchmark](https://huggingface.co/datasets/OpenSTEF/liander2024-energy-forecasting-benchmark) has 55 target series at 15-minute resolution, with per-target `train_start`, `benchmark_start` and `benchmark_end` metadata. The screen pinned revision `ec28635e20a12927f3323a2dc18a0719a361b56d`, downloaded every one of the 55 load-measurement Parquet files anonymously (40,371,354 bytes total), parsed each file and recorded a SHA-256 in [`LIANDER_2024_55_TARGET_SCREEN.json`](data_audit_manifests/LIANDER_2024_55_TARGET_SCREEN.json). The source card reports CC BY 4.0. Liander's source disclaimer says its open-data files may be copied, distributed and reused with attribution as “Liander” plus the publication year. Weather and day-ahead price data are also CC BY 4.0 but were not needed for this load-only screen; consumption profiles were omitted because the card says the upstream profile source has no license, only permission to use it in this dataset. [Liander terms](https://www.liander.nl/over-ons/open-data/disclaimer).

Each task is a separate target series, not a pooled 55-target task: the MLP takes 96 past quarter-hour values and predicts the next 96 quarter-hour values. Windows with missing load values or timestamp gaps were removed. The published pre-benchmark interval was divided chronologically 80/20 into training and validation, and the published benchmark interval was held out for test. Train origins advanced hourly; validation/test origins advanced every four hours. Scaling was fitted only on the training interval. For every target, the whole training partition was one batch per epoch. The actual largest training partition had 1,105 windows; for a five-layer width-512 network its hidden-activation lower bound is about 10.8 MiB, far below the available 6 GiB.

Fifty-two targets had enough examples for two GPU pilots using the repo's `TabularMLP`, MSE and Adam `1e-3`, full-batch, 30 epochs, one fixed seed per target: `[16,16]` and `[128,128]`. The wider model improved test R² on 52/52 pilots and beat last-value persistence MAE on 42/52. Its test R² ranged from `-1.19` to `0.42`, with median `0.15`; `[16,16]` median test R² was `-0.40`. Thus the tested models were unsaturated and width-sensitive, but absolute forecast skill was weak; retain these only as provisional stress tasks, not competitive forecasting claims. The exact per-target metrics, payload sizes/hashes, splits and dispositions are in the [55-target Markdown screen](data_audit_manifests/LIANDER_2024_55_TARGET_SCREEN.md), [CSV](data_audit_manifests/LIANDER_2024_55_TARGET_SCREEN.csv), and [JSON manifest](data_audit_manifests/LIANDER_2024_55_TARGET_SCREEN.json).

**Disposition:** keep 51 individual target tasks provisionally. Cross out `station_installation/SS Stiens`, `station_installation/RS Waskemeer`, and `station_installation/OS Drachten` because the published pre-benchmark period produced no training windows or fewer than 100 full-batch training windows under this 24-hour task; their empirical difficulty is therefore unverified. Cross out `mv_feeder/RS Roodwillingen (Duiven)` because the target metadata says “Roodwillingen” while the only same-group file is named “Roodwilligen”; the identity mapping needs source clarification. All 51 retained tasks still lack runner/provider integration, ADP-variant pilots, repeated seeds, and the full vanilla grid. No pooled-across-target task was screened.

### K3. What “no saturation” can and cannot mean here

No static source check can guarantee that a model will not reach a ceiling: saturation is an empirical property of the exact split, target construction, metric, preprocessing, optimization budget, seed and model. Four runner-backed dataset families, five standalone UCI forecasting pilots (four retained provisionally and UCI Traffic Flow Forecasting crossed out for unresolved source-scaling provenance and underperformance versus persistence), and seven standalone activity-window dataset families have vanilla MLP pilots (HAR, HARTH, MHEALTH, PAMAP2, OPPORTUNITY, four WISDM sensor/device routes, and HHAR). Apnea-ECG wider models collapse to the majority class; MIT-BIH accuracy is inflated by imbalance. The supplemental audit also includes the NEMAR on003810 EEG pilot and SM-RS survey-response pilots. These findings apply only to tested settings, not all model variants, seeds, or budgets. No pilot was run for the other main-ledger candidates.

### K4x. RARD / RARD II recommender logs: Dataverse access and full-batch gates

The 2017 [RARD paper](https://www.dlib.org/dlib/july17/beel/07beel.html) documents a pointwise click-prediction table with one row per displayed recommendation, source and recommended document IDs, rank/set features, algorithm context and click time. It reports 57,435,086 recommendation rows in 7,360,026 sets, 77,468 clicks (0.135% CTR), and a roughly 9.5-million-document corpus. It provides a filtered implicit matrix retaining only sets where at least one item was clicked (63,923 source-document rows; 7,502,182-byte file according to Dataverse search metadata). The article states CC BY 3.0 and explains that clicks/non-clicks are noisy because crawler impressions are not identified. The [RARD II paper](https://arxiv.org/abs/1807.06918) reports 93,955,966 recommendations, 13,482,392 response sets and 113,954 clicks across 24 million items.
The anonymous Harvard Dataverse search API returned HTTP 200 and listed the RARD record and filtered matrix file. That file's search metadata says `restricted=false` but also `canDownloadFile=false`; a direct anonymous range request to file ID `3027416` returned HTTP 403 from this machine. This does **not** establish a login requirement, but the actual file bytes and direct no-gate downloadability remain unverified. I did not download either release.

The logged table is a candidate-item click task a plain MLP could express after numeric/categorical feature construction. However, even the reported row count makes the required full-batch maximum model infeasible: at an illustrative 80% train partition, the `[512]*5` float32 hidden activation lower bound is 438.2 GiB for RARD and 716.8 GiB for RARD II, before inputs, gradients or optimizer state. Dense one-hot document IDs would be much larger, and metadata text is not part of the released log. **Cross out both releases for this repo's all-training-rows batch profile**; their CC BY statement passes rights, but task difficulty was not piloted after the capacity gate. Dataverse search and file-endpoint evidence, the filtered-matrix details, and limitations are in [`RARD_RECOMMENDATION_SCREEN_20261024.json`](data_audit_manifests/RARD_RECOMMENDATION_SCREEN_20261024.json).

### K4y. Tenrec: four recommendation scenarios

The [official Tenrec page](https://tenrec0.github.io/) describes four files—QK-video, QB-video, QK-article and QB-article—with roughly 5 million users and 140 million interactions overall. It reports both positive and true-negative feedback plus context fields, so each scenario could support a row-wise supervised response classifier using ordinary numeric/categorical inputs to a dense MLP. This is not automatically a candidate-set ranking metric, and sequence recommendation claims would require a separate task construction.

The source directs users to read terms before downloading and limits use to research purposes. The [Tenrec paper](https://arxiv.org/abs/2210.10629) describes CC BY-NC 4.0; this fails the user's requirement for unrestricted open reuse. The official download endpoint timed out when opened for this audit, so anonymous byte retrieval was not verified. At the approximate 140-million-row collection scale, a 70% training partition contains 98 million rows. Five width-512 float32 hidden activations alone require about 934.6 GiB, against the repository's 6 GiB device, before inputs, gradients, optimizer state or workspace. No payloads were fetched and no MLP difficulty pilot was run.

**Cross out all four scenario files** for terms-gated/non-commercial rights and full-batch scale. The file-level route states, source evidence, arithmetic and limits are recorded in [`TENREC_SUPERVISED_TABULAR_SCREEN_20261024.json`](data_audit_manifests/TENREC_SUPERVISED_TABULAR_SCREEN_20261024.json). This closes Tenrec as a newly identified candidate; it does not imply an internet-wide census of every dataset release.
